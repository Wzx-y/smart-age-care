# 安全与隐私

## 通知与审计安全边界

通知读取要求 `care:notification:view`，审计查询要求 `care:audit:view`。服务端从可信成员上下文确定租户和接收范围，广播通知仅在所属机构可见；通知去重键、资源 ID 和审计关联 ID 不得由浏览器覆盖。通知标题与审计事件不得携带姓名、联系方式、病历、异常说明、交接正文、附件 URL、对象键、令牌或存储凭据。审计清理仅由服务端按照合规保留期执行，云端需记录任务运行与清理结果。

## 运营报表与导出安全边界

报表读取要求 `care:report:view`，导出创建要求 `care:export:manage`，下载签名要求 `care:export:download`。每次读取、创建和下载均从可信租户与成员上下文确定范围；任务记录不包含长者姓名、联系方式、评估、服务记录正文或附件。签名 URL 只在响应中短时使用，不能写入浏览器持久化状态、日志或审计正文。私有存储桶必须配置生命周期规则清理过期对象，应用层状态到期后立即拒绝再签发访问地址。

## 基础资料授权边界

基础资料写操作必须通过 `care:master-data:manage` 权限，并只在可信租户上下文内执行。浏览器不得提交或覆盖 `tenantId`、`actorId`、审计动作或目录维护人。房间、床位和目录项的审计只保留资源 ID、动作、操作者和时间；设备配置摘要与目录说明按机构数据范围受控读取，不写入通用审计正文。

## 密钥管理

真实密钥只存放在 GitHub Secrets、Vercel 或 Supabase 环境变量。`.env.example` 仅描述名称与格式。禁止客户端打包 `OPENAI_API_KEY`、Supabase service-role key、数据库口令或 RuoYi 服务令牌。

## 权限与隔离

RuoYi 负责认证、租户、角色和数据范围。每次服务端访问同时校验身份、当前租户、模块权限和记录范围；不信任前端传入的 tenantId。高风险权限、导出和租户切换写入不可抵赖审计日志。

入住确认与退住审计只写入租户、操作者、动作、目标记录与关联 ID，不写入姓名、病历、风险说明、退住原因或联系方式。审计写入与入住状态变更使用同一事务；若审计记录无法写入，整笔确认或退住必须回滚。

入住写操作的幂等记录只保存作用域、请求 SHA-256 指纹、资源 ID、状态和版本号，不保存请求原文、姓名、联系方式或照护信息。幂等键由浏览器为单次操作生成；服务端需在合规保留窗口后清理已完成记录，清理任务的部署与监控在云端运维阶段完成。

## 文件与日志

附件存储于私有桶；服务端仅为当前租户下 `PENDING_UPLOAD` 的附件签发短时直传地址，服务角色密钥和对象键绝不返回浏览器。浏览器直传时不得附带 Gateway Bearer Token；完成确认由服务端读取对象元数据并严格比对已登记的媒体类型和字节数。日志禁止记录身份证号、完整病历、口令、令牌、附件 URL、对象键和模型提示内容；使用追踪 ID 关联排错。

长者 360 聚合只允许当前可信租户内的关联记录，不以跨服务 ID 回退查询其他租户数据。联系人与评估更新、删除均由资源版本和当前长者范围共同约束；评估引用只保存 ID，不复制风险说明或照护正文。附件预览/下载 URL 仅在用户动作时内存中使用，禁止写入本地存储、审计正文和应用日志。

## AI 与删除

模型调用仅发送完成任务所需的最小化、脱敏字段；回答不展示思维链，且不可作为医疗结论。删除采用冻结、审批、导出、延迟清理与审计证明流程；法定留存数据须在删除策略中排除。

## 护理闭环安全边界（阶段 3 源码）

护理计划、任务和服务记录的仓储查询与更新均以可信 `tenant_id` 限定，计划和任务的跨租户 ID 查询统一返回 `404`。计划发布和任务完成采用事务、行锁或乐观锁防止并发操作产生部分写入；服务记录仅保存执行人 ID、任务 ID、完成时间和结果说明，不将完整长者档案复制到审计或幂等数据中。

`assigneeId` 不信任浏览器输入：护理服务经 RuoYi 成员目录验证其当前机构归属和对应角色权限，Gateway 负责传递可信租户上下文。护理领域已使用持久化幂等记录，但幂等表不保存完整档案、任务原文或服务记录；只保留指纹、资源引用、状态、版本和必要的异常/结案说明。生产发布前仍须用实际 RuoYi、Gateway 和 MySQL 部署验证成员校验、到期清理与监控。

## 入住与床位闭环（阶段 5 源码）

入住评估结论、调床理由、清洁结果与退住原因属于业务受控记录，只在授权租户内读取；通用审计日志仅保留动作、操作者、关联入住单/长者/床位 ID 与时间，不复制敏感正文。调床和评估的跨租户资源查找统一返回 `404`，不暴露资源是否存在。

护理任务审计只保留 `CARE_TASK_STARTED`、`CARE_TASK_COMPLETED` 或 `CARE_TASK_EXCEPTION` 动作、任务 ID、关联长者 ID、操作者和时间；服务记录与异常说明不复制到审计正文。任务写操作由服务端按当前可信身份校验执行成员，跨租户任务查询为不可枚举 `404`。

## 机构成员与角色隔离

成员管理请求中的 `X-Tenant-Id` 只是浏览器选择的候选机构，Gateway 在转发 `/care/**` 或 `/system/tenant-members/**` 前必须通过内部成员目录复核“令牌用户 + 租户”为启用成员。Gateway 删除浏览器提供的内部用户、租户和内部凭据头，只注入验证后的上下文；`ruoyi-system` 缺少该内部凭据时拒绝成员管理请求。

机构角色保存在 `care_tenant_member_role`，权限查询同时绑定租户、用户、角色、角色菜单和启用状态。成员停用、系统账号停用、角色停用或菜单停用均不会返回业务权限。成员新增、角色替换、成员启停与角色数据范围变更使用 RuoYi 操作日志；日志不记录账号口令、令牌或业务档案正文。
