# 产品需求

## 14. 通知中心与统一审计

系统应在护理任务超过计划时间、护理任务被标记异常、入住确认和班次交接提交时产生站内通知。通知可以面向指定成员或当前机构广播；成员仅可读取当前机构内属于自己或机构广播的记录，并可单条或全部标为已读。通知正文只使用固定业务标题和资源关联，不复制病历、异常说明、交接内容或附件信息。

机构管理者可按资源类型、动作和操作者查询最近 100 条统一审计事件。审计合并入住/护理、基础资料和导出操作轨迹，保留租户、操作者、动作、资源 ID、关联长者 ID 与时间；审计保留期默认 2555 天，由受控服务端任务清理，任何清理均不得绕过机构合规配置。

## 13. 运营报表与受控导出

机构管理者可按起止日期查看运营汇总：在院长者、启用床位、占用床位、床位使用率、入住申请、退住、计划护理任务、已完成任务、异常任务、任务完成率、服务记录和开放跟进项。统计周期最大 367 天，所有指标仅从当前租户的真实业务表聚合。

导出仅支持 `OPERATIONAL_SUMMARY_CSV`，创建后先进入队列，由服务端工作器生成私有 CSV 并在 24 小时后过期。下载使用单次 5 分钟签名 URL；接口响应绝不返回存储对象键、服务密钥、导出失败堆栈或长者身份/照护正文。创建、完成、失败、下载和过期均写入最小审计记录。

运营报表工作台提供起止日期筛选、实时指标概览、周期执行明细与导出中心。Gateway 模式通过认证会话请求报表、创建导出任务并在用户点击下载时获取短时地址；页面不保存地址或对象键。演示模式保留相同的筛选、创建与状态交互，但不生成真实文件。

## 12. 基础资料管理

基础资料由具备 `care:master-data:manage` 权限的当前机构管理员维护，覆盖房间、床位以及 `CARE_ITEM`、`ASSESSMENT_TYPE`、`RISK_LEVEL`、`SHIFT` 四类目录项。房间包含楼栋、楼层、房号、房型和护理单元；床位包含所属房间、床号和设备配置摘要。目录项编码在创建后不可修改，名称、说明、排序和启停使用版本号更新。所有创建、更新和启停操作应保留最小化审计记录。

验收：同一机构内房号唯一，房间内床号唯一，目录编码在“机构 + 分类”内唯一；版本过期、重复编号、状态不满足前置条件均返回 `409`；跨机构资源不枚举且返回 `404`。

## 1. 身份与租户

机构管理员注册机构并完成首位管理员认证。登录后所有查询和写入必须带当前 `tenant_id`；切换租户仅在用户拥有该租户成员资格时可用。异常登录、无租户上下文、角色缺失或权限不足时拒绝操作并记录审计。

验收：用户只能看见授权机构数据；退出登录后回到独立 SaaS 登录页；成员邀请、角色变更和租户切换都有审计记录。

## 2. 长者档案

字段：姓名、性别、出生日期、房间、床位、入住日期、紧急联系人、过敏与风险提示、照护等级、状态、附件引用。状态为待入住、在院、外出、出院、已故；状态变更必须记录原因和执行人。

业务规则：一名在院长者同一时间只能绑定一个有效床位；删除改为受权限控制的逻辑归档；重点风险必须在档案首页和每日任务中可见。

验收：支持搜索、筛选、查看、创建、编辑、归档和导出；所有数据操作均受租户和数据范围约束。

## 3. 入住与床位

房间字段：楼栋、楼层、房号、房型、护理单元、状态。床位字段：床位号、设备配置、卫生状态、占用状态、预留截止时间。入住单状态为待评估、待分配、待确认、已入住、已取消。

规则：仅空闲且通过卫生校验的床位可分配；床位被预留或占用后不可重复分配；确认入住时原子更新入住单、床位和长者档案。

## 4. 护理计划与执行

计划字段：长者、风险依据、计划名称、服务频次、开始结束日期、责任人、执行状态。任务字段：计划、计划日期、计划时间、执行人、任务状态、异常说明、服务记录。

任务状态为待处理、进行中、待确认、已完成、已逾期、已取消。完成需记录执行人和时间；异常任务必须填写说明并创建跟进项；班次交接仅可签收已完成或已说明的任务。

## 5. 设备与告警

设备字段：设备编号、类型、安装位置、在线状态、电量、最近心跳、最近巡检、下次维护、使用状态。告警状态为待确认、已确认、已派单、处理中、待复检、已关闭。

高优先级告警确认后必须在规则时限内派单；关闭前需填写处置结果、维修记录和复检结论。设备总览与告警处置必须为独立视图。

## 6. 智护小助理与导出

助手只回答系统操作路径和经审核的养老服务知识；显示检索与答案整理状态，不展示模型思维链；每次回答带医疗与应急免责声明。导出按机构、权限和时间范围生成，文件过期且下载受授权控制。

## 7. 护理计划与任务闭环补充

护理计划以长者为主体创建草稿，字段包括计划名称、服务频次、开始日期、结束日期和责任人。创建人由当前 Gateway 已认证操作者确定，客户端不得覆盖。结束日期早于开始日期时拒绝保存。

同一长者的计划版本在其租户范围内递增。发布仅允许草稿计划，并要求客户端携带当前计划版本；发布时使该长者的其他已发布计划失效，任何状态或版本冲突均返回 `409`，且不留下部分更新。

护理任务必须引用当前租户内已发布、且服务日期落在计划有效期内的计划；长者 ID 从计划派生，不接受客户端传入。任务可由待处理、进行中或待确认状态进入已完成或异常。完成任务必须同步写入执行人、完成时间和服务记录；异常任务必须填写异常说明。当前代码尚待接入 RuoYi 成员目录校验任务执行人与责任人的机构成员资格。

异常标记与开放跟进项必须在同一事务内创建。跟进项包含异常任务、长者、异常说明、创建人、状态、结案说明、结案人和版本号；仅开放跟进项可以结案，结案请求必须携带版本号。所有护理写操作均必须携带幂等键，同一租户、操作者、操作和请求键的重复提交返回首次结果。

计划可维护结构化任务模板，字段为任务名称、每日计划时间和执行人。指定服务日期生成任务时，只选择当日有效的已发布计划和启用模板；“机构 + 模板 + 服务日期”唯一，重复触发不重复创建任务，并返回本批次实际新增数量。

## 8. 长者档案闭环补充

长者详情工作台应提供健康档案编辑、联系人和评估的新增、编辑、删除以及附件的上传、预览和下载。联系人和评估编辑、删除均须携带当前版本；服务端发生版本冲突时返回 `409`，前端刷新当前长者资料后提示操作者重试。主联系人切换必须在同一事务内完成。

评估记录可以发起护理计划草稿，计划保存评估 ID 而非复制风险说明。被未停用护理计划引用的评估不得删除。360 视图在一个页面显示入住单、护理计划、护理任务和服务记录，便于从评估风险追溯到实际照护执行。

## 9. 入住与床位闭环补充

入住评估必须记录通过或未通过及结论，只有通过状态可进入床位分配。调床需填写理由并校验入住单、原床位和目标床位版本；原床位转为清洁中，目标床位转为占用，长者当前床位同步变更。清洁完成必须录入结果，结果与执行人、时间关联保存。

## 10. 护理执行闭环补充

护理任务从待执行开始，执行成员开始服务后进入进行中；仅当前任务执行成员可完成或标记异常。完成必须填写服务记录并写入执行人、时间与结果；异常必须填写说明并自动创建开放跟进项。仅已完成或异常任务可加入交接，含开放异常跟进项的交接不得提交。

## 11. 机构成员与权限管理

系统管理仅从头像菜单进入。当前机构成员目录显示 RuoYi 系统账号、机构角色、所属部门、数据范围和启停状态。管理员只能将已启用的系统账号加入当前租户，加入时至少选择一个启用角色；成员停用后，Gateway 必须拒绝其对该机构的业务请求。

机构角色采用“租户 + 用户 + RuoYi 角色”关联，不直接以全局 `sys_user_role` 推断养老业务权限。RuoYi 仍是角色定义、菜单权限、部门树和数据范围的权威来源；成员角色变更只影响当前机构，角色数据范围变更按 RuoYi 的角色管理权限执行。所有成员新增、启停、角色授予和数据范围变更写入操作日志。
