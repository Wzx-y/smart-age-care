## 目标与原则

目标是在不破坏现有 SaaS 体验的前提下，将示例交互替换为受 RuoYi Cloud 管控的真实业务能力，并为养老设备接入预留可扩展路径。所有构建、测试、数据库迁移和部署仅在 GitHub Codespaces、GitHub Actions 或授权云环境执行。

## 目标架构

首期部署 5 个应用服务与 1 个 IoT 接入组件：`ruoyi-gateway`、`ruoyi-auth`、`ruoyi-system`、`care-service`、`device-service` 和 EMQX。Nacos、Redis、关系型数据库、对象存储属于基础设施，不计为业务服务。AI、导出和厂商协议适配首期保留在对应业务服务模块内，随规模再拆分。

## 阶段 0：云端基线与契约冻结

工作内容：在 GitHub 建立仓库和 Codespaces；确认 RuoYi Cloud 版本、Java 21、数据库选型和 Supabase 使用范围；锁定 Gateway 前缀、错误码、JWT 租户声明和 OpenAPI 契约。

交付：可用 Codespaces 环境、已配置的 Secrets/Variables、后端仓库或 `backend/` 目录决策、接口版本规范。

验收：GitHub Actions 完成前端 baseline 检查；不在本机执行任何命令。

## 阶段 1：身份、租户与前端壳替换

工作内容：部署 RuoYi Gateway/Auth/System；实现当前用户、可访问租户、角色权限和审计接口；React 从本地登录状态切换到真实 Token、刷新、登出和租户上下文。

交付：`GET /me`、租户切换、菜单权限、403/401 处理、前端 API 适配器与模拟数据开关。

验收：不同租户用户无法读取彼此档案；令牌过期、无权限和网关不可用都有可恢复提示与追踪 ID。

## 阶段 2：长者与入住床位闭环

工作内容：实现 `care-service` 的长者、联系人、风险、房间、床位和入住单；实现乐观锁床位分配、入住确认事务、逻辑归档和审计。

交付：真实长者档案 CRUD、房间床位查询、入住调度 API、数据库迁移与服务测试。

验收：同一床位不能并发分配给两位长者；确认入住后长者状态、入住单和床位状态一致；跨租户请求返回不可枚举的 404。

## 阶段 3：护理计划与任务闭环

工作内容：基于长者评估记录实现护理计划版本、任务生成、执行记录、异常跟进和班次交接；按机构时区生成每日任务。

当前源码进展：已新增 `V4` 至 `V15` 护理迁移、租户范围 JDBC 仓储、计划草稿/编辑/发布/停用 API、可选评估依据引用、任务创建/开始/完成/异常 API、服务记录及按长者/日期/成员的服务端筛选、异常跟进项/结案、护理领域幂等重放、任务模板创建/编辑/停用与按日生成批次、Java 单元测试源码和完整 React Gateway 护理工作台。计划发布与任务创建用长者行锁串行化；模板生成由数据库唯一键去重；计划、模板、任务、跟进项以版本号作条件更新。未运行迁移、编译或测试。

阶段 3 源码收口：Gateway 护理工作台已补齐计划编辑/停用、模板编辑/停用、任务开始、服务记录筛选、异常结案和交接入口；成员选择读取真实机构成员目录。剩余的是 RuoYi、Gateway、MySQL 与浏览器端到端验证，不再是页面功能缺口。

交付：计划发布、任务队列、完成/异常/交接接口，前端将现有护理执行页面接入真实数据。

验收：计划变更有版本记录；任务完成可追溯到执行人和时间；异常未处理时不能完成交接。

## 阶段 4：设备与 IoT 接入闭环

工作内容：部署 EMQX；建设设备产品、设备激活、设备凭证、MQTT Topic ACL、遥测标准化、设备影子、告警规则、维修工单与复检。

交付：`device-service`、首批紧急按钮/睡眠监测/毫米波雷达适配器、在线状态和告警事件流、WebSocket/SSE 实时推送。

验收：设备不得直接访问业务数据库；每条遥测和告警均可定位至租户、设备和房间/长者；高优先级告警从确认到关闭全程审计。

## 阶段 5：AI、导出与运营能力

工作内容：导出、运营指标、通知与审计源码已完成；AI 后续接入受控知识库和服务端适配器，提供护理建议草稿、人工确认、脱敏与审计。

交付：运营指标、导出中心、数据范围、受控下载、通知、统一审计与保留策略；AI 保留预设回答，等待服务端编排。

验收：AI 不直接生效或控制设备；测试不调用真实模型；导出权限与当前租户和角色一致。

## 阶段 6：质量、发布与运维

工作内容：补齐 TypeScript 迁移、单元/集成/Playwright 套件、数据库迁移演练、观测性、预览部署和生产审批。

交付：GitHub Actions 全质量门禁、部署后烟测、回滚手册、版本化验收报告。

验收：所有质量门禁有云端记录；生产部署必须经人工审批；健康检查失败给出回滚建议而不自动删除数据。

## 推荐实施顺序

业务源码已完成阶段 1、2、3 及阶段 5 中非 AI 项目的收口。下一步按阶段 0 的云端验证、阶段 6 的质量门禁推进；设备真实接入仍在阶段 4，AI 服务端编排仍在阶段 5。不要在身份、租户、数据模型和审计未得到云端验证前接入真实设备或真实 AI 密钥。
