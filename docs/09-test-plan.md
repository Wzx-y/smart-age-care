# 测试计划

## 通知与统一审计测试

- Java 单元测试：当前成员只能读取本人及机构广播通知、去重键阻止重复逾期提醒、单条/全部已读不跨机构；审计筛选、最大条数和租户范围正确生效。
- Node 契约测试：通知读取、已读和审计查询均使用 Gateway Bearer Token，浏览器请求不包含 `tenantId`、接收成员或审计动作写入字段。
- 云端集成测试：逾期扫描幂等、通知与产生事件同事务回滚、广播与个人通知可见性、审计跨租户 `404/403`、保留清理与导出/基础资料审计联合排序。

## 运营报表与导出测试

- Java 单元测试：报表只以当前租户聚合、无效/超长周期被拒绝、导出创建写入可信租户与审计、工作器仅写入匿名聚合 CSV、未过期 `READY` 任务才能签名下载。
- Node 契约测试：运营报表查询、导出创建和签名下载均使用 Gateway Bearer Token，浏览器请求不包含 `tenantId`。
- 前端端到端测试：Gateway 模式切换统计周期后显示服务端汇总；创建任务后显示 `QUEUED`/`GENERATING`/`READY` 状态；只有 `READY` 可触发下载授权；`FAILED`、`EXPIRED` 不显示下载操作；演示模式不产生真实文件请求。
- 云端集成测试：MySQL 聚合口径、工作器并发领取、对象存储失败状态、过期后拒绝访问、角色权限变化后下载拒绝、对象存储生命周期清理和跨租户 `404`。

## 基础资料管理测试

- Java 单元测试：当前租户查询、重复房号冲突、版本过期不写入、含启用床位的房间不能停用、占用或关联长者的床位不能停用、目录项启停审计。
- Node 契约测试：Gateway 路径、Bearer Token、版本化请求体和禁止传入 `tenantId`。
- 云端集成测试：MySQL 唯一约束、并发版本冲突、停用床位后入住预留/确认状态机拒绝写入、跨租户 `404` 与权限 `403`。

## 范围

业务客户端契约测试必须断言请求包含 `/care/api/v1` 前缀，防止绕过 Gateway 直接访问服务路径。新增基础资料、护理工作台、审计工作台和机构目录的真实 Gateway E2E 后，才可将对应模块标记为完成。

- 单元：租户范围解析、床位可分配规则、任务状态机、告警状态机、导出脱敏、AI 输出过滤。
- Java 单元：`care-service` 的租户上下文、长者状态、入住并发控制和护理任务状态机；`device-service` 的遥测标准化和告警状态机。
- 集成：RuoYi 身份上下文、业务服务事务、RLS 策略、对象存储签名、AI 适配器模拟和错误重试。
- 端到端：注册/登录、创建长者、入住分配、生成计划草稿、人工确认、任务完成与异常、告警派单关闭、导出、权限隔离和失败重试。
- 视口：桌面和 390 x 844 移动端均覆盖登录、核心任务、设备处置和助手对话。

## 通过条件

AI 测试使用固定模拟响应，不调用真实模型或付费密钥。PR 合并前必须通过 lint、类型检查、单元、集成、生产构建和 Playwright 测试；部署后烟测验证健康检查、登录、租户隔离和关键只读查询。

## 当前状态

`care-service` 与 RuoYi Cloud 均已有 Maven 测试源码，GitHub CI 分别执行 `backend/pom.xml` 和 `backend/ruoyi-cloud/pom.xml` 的 Java 21 `mvn verify` 作业；尚未在云端执行。TypeScript、后端集成和 Playwright 测试套件仍未完成，不得把该状态描述为已通过。

`tests/integration/codespaces-stack.test.mjs` 对全容器化 Codespaces 编排做静态检查：必须包含 MySQL、Redis、Nacos、RuoYi Auth/System/Gateway、`care-service` 与前端服务；密钥只允许来自被忽略的 `.env.codespaces`；启动脚本必须以已认证的 MySQL 查询作为初始化门槛，不能只依赖 `mysqladmin ping`，并将 RuoYi、护理和 Gateway SQL 导入明确指定到各自数据库；浏览器请求通过 `/gateway` 代理。该测试不替代 Codespaces 实际启动、登录或端到端证据。

`care-service` 的单元测试直接声明 `mockito-core` 测试依赖，确保 GitHub Actions 的测试编译类路径包含测试替身 API；该依赖由 Spring Boot BOM 管理版本。

Codespaces 启动基线现由 `infra/codespaces/compose.yaml` 与 `scripts/codespaces/` 提供。Playwright 依赖尚未进入锁文件，必须在 Codespaces 完成依赖锁更新、浏览器安装和真实 Gateway 用例后，才可以替换 CI 的 E2E 就绪标记；在此之前该标记不是测试通过证据。

入住床位预留已增加单元测试源码，覆盖同租户成功预留、跨租户资源返回不可枚举的 404、占用/未准备床位拒绝、入住单或床位版本冲突，以及入住单更新冲突时的事务回滚信号。实际数据库回滚仍须在后续 GitHub Codespaces 或 Actions 中，以 MySQL 迁移后的集成测试验证。

确认入住已增加单元测试源码，覆盖床位、长者、入住单与审计事件的成功协作，床位状态不符时的写入拦截，以及末步入住单更新冲突时的回滚信号。后续集成测试需断言发生冲突后床位保持“已预留”、长者保持“待入住”、入住单保持“待确认”，并且没有审计行。

退住已增加服务与 Gateway 客户端单元测试源码，覆盖已入住长者解除床位绑定、床位转为“清洁中”、入住单状态与审计事件协作，床位非占用状态拦截，以及末步入住单更新冲突时的回滚信号。云端 MySQL 集成测试还必须验证退住原因不会写入审计表、床位完成卫生准备前不可再次预留、同一幂等键重放不重复写入，以及退住与归档并发时不绕过状态和床位约束。

前端入住 API 适配器已增加 Node 测试源码，覆盖 Gateway 路径、Bearer Token、幂等键、版本号及禁止客户端传递 `tenantId`。页面级联调必须等待真实入住单与床位查询接口可用后再进行。

入住调度查询已增加 Java 服务测试源码，覆盖从当前租户上下文读取入住单和按占用状态读取床位；前端 API 测试源码覆盖读取路径、Bearer Token 与禁止传递 `tenantId`。后续云端集成测试需验证两个查询 SQL 不会返回其他租户记录，端到端测试需验证分配、确认和 `409` 后自动刷新。

入住幂等服务已增加单元测试源码，覆盖首次执行、成功重放、同键不同内容冲突、租户与操作者隔离、处理中请求拒绝、无效键以及唯一键竞争后的当前读重放。云端 MySQL 集成测试必须验证重复 HTTP 请求只产生一次床位/入住单/审计写入，失败事务不残留幂等记录，跨租户和跨操作者不能重放彼此结果。

## 入住与床位闭环（阶段 5 源码）

覆盖未完成或版本过期的评估不得进入待安排；评估通过后才允许分配；调床需要原/目标床位和入住单版本命中，并同时更新长者、两张床位和入住单；清洁结果为空时拒绝完成；入住审计查询不得跨租户返回轨迹。前端 API 测试验证请求不携带租户字段，并传递评估、调床与清洁必要字段。

护理执行补充覆盖：仅待执行任务可开始；开始后状态与版本变化并写最小审计；完成时服务记录与任务状态同事务提交；异常时跟进项同事务创建；版本冲突、非执行成员和跨租户请求均不得写入。云端端到端测试应验证开始、完成、异常、结案和交接的连续操作。

## 机构成员与权限管理

已新增 RuoYi System 服务单元测试源码，覆盖启用成员返回租户角色菜单权限、未启用成员不返回权限、机构成员加入时写入机构角色关联，以及拒绝停用或不存在角色。前端 Node 单元测试源码覆盖 `/system/tenant-members` 的 Gateway 路径、Bearer Token、`X-Tenant-Id` 请求头、RuoYi `code: 200` 成功信封和禁止在请求体写入 `tenantId`。

云端集成与端到端测试仍需验证：同一账号在两个机构使用不同角色时权限不同；成员停用后 Gateway 立即拒绝当前机构业务请求；浏览器伪造内部租户头或直接访问 System 服务被拒绝；角色替换事务不留下孤立关联；角色数据范围变更对长者、护理、导出查询生效。未执行这些云端检查前，不得宣称机构权限联调已通过。
